## 一、幕后黑手：什么是 WebRTC？它为什么能穿透代理？

**WebRTC (Web Real-Time Communication)** 是一项由 Google 推动并被 W3C 采纳的现代网络标准，它允许浏览器在无需安装任何第三方插件或软件的情况下，直接在网页之间进行点对点（P2P）的高清语音、视频通话与大文件实时互传。

这项优秀的通讯技术在跨境出海领域，却演变成了最致命的“超级泄密通道”：

```text
               +---------------------------------------------+
               |        你的电脑 (位于中国大陆，真实公网IP A)  |
               +---------------------------------------------+
                        |                             |
     [HTTP / SOCKS5 代理网关]                   [WebRTC STUN 探测通道]
                        |                             |
      (经过代理服务器转换封装)                 (绕过所有系统 HTTP 代理设置!)
                        |                             |
               [海外代理出口 IP B]                     |
                        \                             /
                         \                           /
                          +-------------------------+
                          |  亚马逊/PayPal/TikTok 风控服务器  |
                          +-------------------------+
                          | 审查结果: 
                          | - HTTP 出口 IP: B (美国)
                          | - WebRTC 本地真实 IP: A (中国广东电信!)
                          | -> 判定: 恶意伪装代理跳板，立刻封禁处理!
                          +-------------------------+
```

### 为什么它能轻易绕过你的代理？
*   普通代理软件（如通过 Clash 或系统代理）通常只接管标准的应用层 **HTTP/HTTPS 与 TCP 流量**；
*   而 WebRTC 在建立 P2P 直连通道时，底层会通过 **STUN (Session Traversal Utilities for NAT)** 服务器发送 UDP 数据包探测本地网卡的真实物理网络环境；
*   **这种 UDP 握手包具有直接穿透本地代理网关的“特异功能”！** 目标网站只要在页面中嵌入短短几行 JavaScript 代码，就能在 0.05 秒内直接读取出你本机的**真实中国运营商公网 IP** 以及**局域网内网 IP（如 192.168.x.x）**！

## 二、一秒自测：你的浏览器是否存在 WebRTC 泄漏？

不要盲信任何代理软件上的绿灯提示，请立即在当前使用的浏览器中进行一次彻底的“泄密排查”：

### 测试步骤：
1. 保持当前代理开启；
2. 打开业界公认最权威的深度检测平台：[browserleaks.com/webrtc](https://browserleaks.com/webrtc)
3. 重点观察结果面板中的 **“IP Address Detection”** 区域：

```text
+-----------------------+-----------------------------+-----------------------------+
| 核心检测字段          | 危险/泄漏状态 (触发关联封禁) | 完美安全状态 (真正安全)      |
+-----------------------+-----------------------------+-----------------------------+
| Public IP Address     | 赫然显示出你本机的真实国内 IP| 显示与代理一致的海外 IP，或空|
| Local IPv4 (内网地址) | 暴露真实的 192.168.x.x 局域网| 替换为混淆随机哈希，或完全隐藏|
| STUN Server Binding   | 返回包含中国运营商的节点记录| 仅返回海外代理节点或直接受限 |
+-----------------------+-----------------------------+-----------------------------+
```

*   **红色警报：** 只要在 **Public IP Address** 中看到了你的真实中国电信/联通/移动 IP，说明你的网络伪装在各大跨境电商平台眼里等于**“彻底裸奔”**！

## 三、4 步彻底封堵 WebRTC 泄漏的实操方案

针对不同的使用场景，推荐采用以下针对性解决方案：

### 方案一：在防关联指纹浏览器中开启“内核级替换”（最彻底推荐）
如果你使用的是 **AdsPower** 或同类专业指纹浏览器：
1. 打开环境配置面板，进入 **“高级设置 (Advanced)”** -> 找到 **“WebRTC”** 选项；
2. **正确设置项：**
   *   **首选模式：选择【替换 (Replace)】**（AdsPower 会在 Chromium 底层将本地 IP 强制篡改伪装为与绑定的代理 IP 完全一致，在平台看来是最真实、无破绽的海外正常浏览器）；
   *   **备选模式：选择【禁用 (Disable)】**（直接彻底关闭 WebRTC API 功能，彻底杜绝数据回传）。
3. 保存后重新打开环境测试，BrowserLeaks 上的泄漏风险瞬间清零！

### 方案二：普通 Chrome 浏览器安装专用拦截扩展
如果你是在日常调试中临时使用普通 Google Chrome 浏览器：
1. 在 Chrome Web Store 应用商店中搜索并安装开源插件：**`WebRTC Control`** 或 **`WebRTC Leak Shield`**；
2. 点击插件图标，将其运行模式切换为 **“Disable non-proxied UDP (禁用非代理的 UDP 通信)”**；
3. 此举能强行阻断所有未经过代理中继的 STUN 探测请求。

### 方案三：Firefox（火狐浏览器）从根源永久关闭 WebRTC
Firefox 允许用户在底层配置文件中直接硬编码关闭该协议：
1. 在 Firefox 地址栏输入：`about:config` 并按下回车，点击接受风险；
2. 在搜索框中输入：`media.peerconnection.enabled`；
3. 双击该配置项，将其布尔值从 `true` 修改为 **`false`**；
4. 重启火狐浏览器，WebRTC 功能将被物理彻底禁用。

### 方案四：在代理客户端中开启 TUN 虚拟网卡模式
在电脑端使用的 Clash Verge 或 Sing-box 客户端中：
*   开启 **TUN 模式（启用系统虚拟网卡服务）**；
*   TUN 驱动会在操作系统内核网络层，将所有的 UDP 数据包无差别强行拦截并封装进加密代理隧道，从而彻底剥夺 WebRTC 旁路直连国内网络的机会。
